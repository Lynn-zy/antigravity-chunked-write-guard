# 分段写入规范（Chunked Write Guard）

<!-- 当前生效档位：500 行 · 标准档（可在 Write Guard 侧边栏面板一键切换 700 / 500 / 300 档） -->

为避免单次输出过长触发模型流式超时（`The stream was interrupted`）并导致零进度重试循环，写入或大段修改文件时遵守以下预算：

1. **单次写入目标 ≤ 500 行**：每次 `write_file`（含 `Append: true`）或 `edit_file` 的新内容尽量控制在 500 行以内。
2. **长文件必须分步构建**：预计超过 500 行的文件（尤其是单页 HTML 原型、大型组件、长文档或长脚本），必须拆成多步落盘：
   - 第 1 步用 `write_file` 写入精简骨架（框架结构、核心样式或接口声明，≤ 500 行）；
   - 后续按功能模块分次调用 `write_file(Append: true)` 或 `edit_file` 逐步补齐，使每次写入都快速落盘。
3. **兜底门禁与断流自愈**：
   - 本地 `PreToolUse` Hook 对单次写入设有硬兜底线（**800 行**或 **48 KB**，以及 `edit_file` 合计超 900 行 / 56 KB）。若被拦截，请直接缩小粒度分段写入，不要原样重试。
   - 若收到断流自愈提示，本轮单次写入强制控制在 **≤ 300 行**以内，确保先成功落盘。
